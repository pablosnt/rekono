# Changelog
All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.0.0/), and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [2.0.0] - 2026-08-21

### Added

- Brand new user interface, rebuilt from scratch with `Nuxt` (https://github.com/pablosnt/rekono/issues/298)
- Optimization and restructuring of the backend from scratch, to make it simpler, faster and safer (https://github.com/pablosnt/rekono/issues/222)
- Triage of the findings as true positive, false positive or won't fix, with a comment to explain the decision (https://github.com/pablosnt/rekono/issues/283)
- Mark findings as fixed manually or automatically when the executions that used to detect them stop reporting them (https://github.com/pablosnt/rekono/issues/284)
- Generation of reports in PDF, JSON or XML with the findings matching the user's criteria (https://github.com/pablosnt/rekono/issues/273)
- Alerting system that notifies each alert's subscribers when a finding matches the alert's criteria (https://github.com/pablosnt/rekono/issues/301)
- Pentesting notes linkable to the rest of Rekono entities with a rich text editor that supports code blocks, tables, task lists and images (https://github.com/pablosnt/rekono/issues/267)
- Integration with VirusTotal to get the reputation, the malicious analysis and the WHOIS information of the identified hosts (https://github.com/pablosnt/rekono/issues/354)
- Integration with HackTricks to link the identified assets with related wiki resources (https://github.com/pablosnt/rekono/issues/271)
- Integration with CVE Crowd to identify which detected CVEs are trending on social media (https://github.com/pablosnt/rekono/issues/301)
- Integration with EPSS FIRST to enrich the vulnerabilities with the EPSS score and percentile of their CVE (https://github.com/pablosnt/rekono/issues/369)
- Integration with VulnCheck NVD++ to enrich the vulnerabilities with the data of their CVE (https://github.com/pablosnt/rekono/issues/369)
- Integration with GitHub Security Advisories to enrich the vulnerabilities with the data of their CVE (https://github.com/pablosnt/rekono/issues/369)
- Integration with Open Source Vulnerabilities to enrich the vulnerabilities with the data of their CVE (https://github.com/pablosnt/rekono/issues/369)
- Integration with EU Vulnerability Database to enrich the vulnerabilities with the data of their CVE (https://github.com/pablosnt/rekono/issues/369)
- Selection of the CVE provider based on the quality of the information provided (https://github.com/pablosnt/rekono/issues/369)
- New monitor job that keeps the vulnerabilities with CVE up to date and cleans the stale executions (https://github.com/pablosnt/rekono/issues/222)
- Support for NVD NIST API keys, which increase the rate limits and speed up the enrichment of the vulnerabilities (https://github.com/pablosnt/rekono/issues/325)
- Defect-Dojo imports can reimport the scans and close the findings that are not detected anymore (https://github.com/pablosnt/rekono/issues/363)
- Get the domain and the geolocation of every host discovered (https://github.com/pablosnt/rekono/issues/337)
- Customization of the HTTP headers sent by the tools, for the whole instance, for one user or for one target (https://github.com/pablosnt/rekono/issues/297)
- Customization of the proxies used during executions, configurable for HTTP, HTTPS, FTP and all the protocols (https://github.com/pablosnt/rekono/pull/265)
- Path in the target ports to limit the scope of the executions (https://github.com/pablosnt/rekono/issues/222)
- Download of the original reports generated by the tools (https://github.com/pablosnt/rekono/pull/264)
- Visualization of the commands executed by each execution (https://github.com/pablosnt/rekono/pull/380)
- Finding pages with the finding metadata, its exposure window and its related findings (https://github.com/pablosnt/rekono/issues/298)
- Metrics pages with more KPIs and stats (https://github.com/pablosnt/rekono/issues/298)
- Creation of findings from user-provided data, like targets, target ports or input technologies, in order to keep the relationships between findings consistent (https://github.com/pablosnt/rekono/issues/340)
- Light and dark themes (https://github.com/pablosnt/rekono/issues/298)
- Users can change their email address (https://github.com/pablosnt/rekono/pull/299)
- Administrators can check the status and the stats of the queues (https://github.com/pablosnt/rekono/pull/266)
- Administrators can enable and disable integrations (https://github.com/pablosnt/rekono/issues/269)
- New default wordlists for CMS, APIs, GraphQL and specific services (https://github.com/pablosnt/rekono/issues/371)

### Changed

- [**BREAKING**] Upgrade `PostgreSQL` version from `14` to `18`, migrating the data of Rekono 1.x automatically in Docker deployments (https://github.com/pablosnt/rekono/issues/386)
- [**BREAKING**] Upgrade required `Python` version to `3.11` (https://github.com/pablosnt/rekono/issues/222)
- [**BREAKING**] The SMTP configuration is stored in the database, so it is removed from the configuration file and from the `RKN_EMAIL_*` environment variables (https://github.com/pablosnt/rekono/issues/222)
- [**BREAKING**] Replace `Redis` by `Valkey` (https://github.com/pablosnt/rekono/issues/373)
- New email templates based on `react-email` for the notifications sent through SMTP (https://github.com/pablosnt/rekono/issues/375)
- Send emails using new threads instead of the `emails-queue` Redis queue (https://github.com/pablosnt/rekono/issues/222)
- Input technologies and vulnerabilities are provided when a scan is created, instead of being saved in the target (https://github.com/pablosnt/rekono/issues/323)
- The `address` field of the hosts is renamed to `ip` (https://github.com/pablosnt/rekono/issues/222)
- Replace the `/api/system/` endpoint by `/api/settings/` and one endpoint for each integration (https://github.com/pablosnt/rekono/issues/269)
- Tool arguments are defined per configuration, so only the inputs that each configuration really needs are requested (https://github.com/pablosnt/rekono/issues/360)
- Backend and frontend Docker images are based on distroless images, so they are smaller and ship less software than the Rekono 1.x ones (https://github.com/pablosnt/rekono/issues/345)
- TLS certificates of the Docker deployment are kept in a volume, instead of the `docker/nginx/tls` directory (https://github.com/pablosnt/rekono/issues/345)
- Executions store the Defect-Dojo test that they create, instead of just knowing that they were imported (https://github.com/pablosnt/rekono/issues/363)
- The Telegram bot creates the authentication of a target port within the `/newport` command (https://github.com/pablosnt/rekono/issues/222)
- The Telegram bot asks for the wordlists, technologies and vulnerabilities that each scan needs (https://github.com/pablosnt/rekono/issues/323)
- The Telegram bot asks for the target port to be scanned (https://github.com/pablosnt/rekono/pull/380)
- The Telegram notifications link to the scans in the user interface (https://github.com/pablosnt/rekono/pull/380)
- Default processes updated with the new tool configurations (https://github.com/pablosnt/rekono/issues/360)
- Use `uv` to manage the backend dependencies and to run the Rekono commands (https://github.com/pablosnt/rekono/issues/342)
- Use `pnpm` to manage the frontend dependencies (https://github.com/pablosnt/rekono/issues/298)
- Upgrade `Django` version to `5.2.17` (https://github.com/pablosnt/rekono/issues/222)
- Upgrade `djangorestframework` version to `3.18.0` (https://github.com/pablosnt/rekono/issues/222)

### Deprecated

- Automatic migration of data from Rekono 1.x to 2.x will be removed in the short term (https://github.com/pablosnt/rekono/issues/386)
- Tool configurations that don't work anymore are marked as deprecated, so they can't be used in new scans but the old executions keep their history (https://github.com/pablosnt/rekono/issues/360)

### Removed

- [**BREAKING**] Remove Rekono Desktop, both the `Electron` applications and the Debian package, so Rekono is deployed with Docker or from source (https://github.com/pablosnt/rekono/pull/385)
- [**BREAKING**] Remove support for Rekono deployments under a specific web path with `rootpath`, since the NGINX configuration, frontend and backend URLs are enough (https://github.com/pablosnt/rekono/pull/299)
- Remove deprecated settings (https://github.com/pablosnt/rekono/issues/222)
- Remove tasks status, because the status of a scan comes from its executions (https://github.com/pablosnt/rekono/issues/222)
- Remove `scheduled_in` from the scans, as it is covered by `scheduled_at` (https://github.com/pablosnt/rekono/issues/304)
- Remove findings fields `first_seen`, `last_seen`, `detected_by` and `is_active` that are replaced by their executions, triage and fixed status (https://github.com/pablosnt/rekono/issues/283)
- Remove the `enable` and `disable` operations over the findings, replaced by the triage and the fixed status (https://github.com/pablosnt/rekono/issues/283)
- Remove steps priority (https://github.com/pablosnt/rekono/issues/222)
- Remove the `/newauth`, `/newtechnology` and `/newvulnerability` commands from the Telegram bot, since these values are requested when they are needed (https://github.com/pablosnt/rekono/issues/323)
- Remove the `Endpoints list for Dirsearch`, `WebLogic` and `WebSphere` default wordlists, whose files are not provided anymore (https://github.com/pablosnt/rekono/issues/386)

### Fixed

- Verify and fix all the tool parsers to support the latest report formats, keeping the support for the previous ones (https://github.com/pablosnt/rekono/issues/339)
- Fix the tool commands, and improve the output that the executions generate (https://github.com/pablosnt/rekono/pull/351)
- Fix `Schedule` and `Repeat` sections of the scan form (https://github.com/pablosnt/rekono/issues/219)
- Fix the creation of multiple engagements in Defect-Dojo to import scans from the same target (https://github.com/pablosnt/rekono/issues/222)
- Fix the Defect-Dojo scan types used for each tool, so the findings are imported as expected (https://github.com/pablosnt/rekono/issues/363)
- Remove the duplicated API field used to sort the data (https://github.com/pablosnt/rekono/issues/222)

### Security

- User sessions are kept in `HttpOnly` cookies instead of the browser storage, and refreshed silently (https://github.com/pablosnt/rekono/pull/365)
- Multi-Factor Authentication (MFA) via authenticator apps or email (https://github.com/pablosnt/rekono/issues/303)
- Administrators decide what can be scanned and what can't, with a denylist of targets, patterns and IP networks (https://github.com/pablosnt/rekono/issues/222)
- Management of multiple personal API tokens with expiration dates (https://github.com/pablosnt/rekono/issues/222)
- New configuration property to enable the encryption of sensitive data like Defect-Dojo API keys, Telegram tokens or authentication credentials when stored in the database (https://github.com/pablosnt/rekono/issues/222)
- New management commands to create, rotate and remove the encryption key (https://github.com/pablosnt/rekono/issues/222)
- Credentials and internal details are removed from the execution commands, outputs and reports (https://github.com/pablosnt/rekono/issues/288)
- Close user sessions and unlink the Telegram bot when the user's password changes (https://github.com/pablosnt/rekono/issues/222)
- New endpoints to manage Content Security Policy reports sent via the `report-to` and `report-uri` directives (https://github.com/pablosnt/rekono/pull/362)
- Docker images run with unprivileged users and without new privileges (https://github.com/pablosnt/rekono/issues/345)
